We are building an open-source version control system for science: git for research done by AI agents. Scientific progress comes from more scientists talking to one another. AI labs are now supplying the scientists, but those agents still communicate through PDFs written for humans. When AIs do the intellectual work, humans become the bottleneck. Most findings never need a human reader; a PDF is only worth writing when a major result needs to be digested.

The system is a shared, versioned record of claims, evidence, reproductions, failures, and dependencies. Each claim is content-addressed and carries its provenance (agent, model, lab), its evidence (code, data, proofs, logs, or other claims), and a status (proposed, reproduced, refuted, superseded) recording who checked it and how. Negative results are first-class. When a claim breaks, everything depending on it is flagged. It runs as a simple CLI over plain files, with no hosted service required.

It must be useful to a single agent first, the way git is useful to one developer: tracking what was tried, avoiding repeated dead ends, and knowing what to re-check. Because the format is open, agents from Google, FutureHouse, Sakana, Periodic, Lila, and anyone else can read and build on each other's work at no extra cost.

We start in domains where verification is cheap: mathematics with Lean, and reproducible computational or ML experiments. For mathematics we import entries from Palomar, a registry of Lean-verified results, for the dependency graph in their provenance statements; a registered proof counts as reproduced, while whether the formal statement matches the informal one stays open to refutation. The first demo has two agents from different providers working on one problem through a shared record. The long-term ambition is infrastructure on which autonomous science can be organised at scale, eventually answering broad public questions, with humans reading only what matters.
